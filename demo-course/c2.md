This is the Demo course: every service, number and answer in it is invented. C2 is one idea: a pipeline is a row of gates, and each gate stops one kind of mistake.

## Read the pipeline {#read-the-pipeline minutes=5}

A job a pull request must pass before it merges is a required job. Read your service's pipeline.

::: oceens
Lendly's pipeline runs three jobs on each pull request: `lint`, `test` and `build`. **All three are required.** After the merge, `deploy` sends Lendly to staging, and a person promotes staging to production.
:::

::: mathutrice
Skywatch's pipeline runs two jobs on each pull request: `lint` and `test`. **Only `test` is required.** After the merge, `deploy` sends Skywatch to staging, and production follows by itself once staging answers its health check.
:::

## Check: predict the pipeline {#predict-the-pipeline minutes=10}

For each change, predict the first job that fails, and whether its pull request can merge. The Instructor's answer explains each one once you send yours.

::: oceens
Two changes to Lendly. Change 1 leaves a line of 140 characters, and `lint` refuses lines over 100. Change 2 makes a loan last 21 days instead of 14, and a test still expects 14.

::: field {#change-1-fails kind=choice options="none|lint|test|deploy"}
Change 1: which job fails?
:::

::: field {#change-1-merges kind=choice options="yes|no"}
Change 1: can its pull request merge?
:::

::: field {#change-2-fails kind=choice options="none|lint|test|deploy"}
Change 2: which job fails?
:::

::: field {#change-2-merges kind=choice options="yes|no"}
Change 2: can its pull request merge?
:::

::: answer

| Change | Fails | Merges | Why                                                                   |
| ------ | ----- | ------ | --------------------------------------------------------------------- |
| 1      | lint  | no     | Every job is required: a lint error blocks the merge.                 |
| 2      | test  | no     | The test still expects 14 days, so it fails before anything is built. |

:::
:::

::: mathutrice
Two changes to Skywatch. Change 1 leaves a line of 140 characters, and `lint` refuses lines over 100. Change 2 sends warnings to a gateway address that does not exist: the tests use a fake gateway, and staging's health check calls the real one.

::: field {#change-1-fails kind=choice options="none|lint|test|deploy"}
Change 1: which job fails?
:::

::: field {#change-1-merges kind=choice options="yes|no"}
Change 1: can its pull request merge?
:::

::: field {#change-2-fails kind=choice options="none|lint|test|deploy"}
Change 2: which job fails?
:::

::: field {#change-2-merges kind=choice options="yes|no"}
Change 2: can its pull request merge?
:::

::: answer

| Change | Fails  | Merges | Why                                                                                                       |
| ------ | ------ | ------ | --------------------------------------------------------------------------------------------------------- |
| 1      | lint   | yes    | Only `test` is required: the lint error does not block the merge.                                         |
| 2      | deploy | yes    | The tests pass on the fake gateway; staging's health check fails, so the change never reaches production. |

:::
:::

## What the gate does not see {#what-the-gate-misses minutes=5}

No pipeline sees everything.

::: field {#sentence kind=text}
Name one mistake your pipeline would let through, and the job that would catch it.
:::

::: answer
**A gate only sees what a job checks.** A page that no test opens can break unseen: a test that opens it, in the `test` job, would catch it.
:::
