# The Student's work is what a ref changes beyond every upstream course branch

A Student's Evidence Project usually starts from their Group's upstream repository, and may bring in the upstream's own course branches, such as a Fallback Branch or a Worked Example. Crediting the Student with that code would show work they did not do; requiring them to work on one branch would miss work pushed elsewhere. **So the Repository reading reads every branch and the head of every pull request, closed ones and those whose branch was deleted included, compares each ref with each upstream course branch, and counts a file as the Student's only if it differs in every comparison, keeping its smallest difference.** Code a Fallback Branch or a Worked Example brought in is credited to that branch, never to the Student, whoever authored the commits.

- The upstream course branches are those whose name starts with `COURSE_PREFIX` in `backend/app/repository_reading/_internal/rules.py` (`RepositoryReader.upstream_branches`).
- `_Analysis._analyse` in `backend/app/repository_reading/_internal/analysis.py` holds the rule: a file equal to its version on any upstream course branch is skipped, and so is a lockfile (`LOCKFILES`).
- A repository GitHub links to the Group's upstream shares its history: one of its refs that cannot be compared with any upstream branch is unreadable, never read on its own. Only a repository GitHub does not link to the upstream is read on its own (`_Analysis._own_history`), where every file it holds is the Student's and its lines are not counted.
- Each Fallback Branch is built on the one before it, and a parent is merged forward into its child: the order of `FALLBACK_CHAIN` in `rules.py` is that build order. `_Analysis._fallback_on` relies on it to find the last-built Fallback Branch the default branch contains, in any version of it, by comparing that branch's parent with the merge base.
- Comparisons are cached by repository and pair of SHAs (`RepositoryReader.compare`), and each ref's analysis is kept in the stored reading by its tip SHA. A refresh lists the repository's branches and pull requests (2 requests while each list fits one page of 100) and recomputes only the refs whose tip changed, unless the upstream branches moved.
- One `RepositoryReader` serves every Student, built once in `app.main` (`default_repository_reading`), so that the comparison cache and the cache of upstream branches are shared; building one per request would lose them.
