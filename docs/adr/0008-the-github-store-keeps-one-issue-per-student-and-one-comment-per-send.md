# The GitHub Store keeps one issue per Student, and one comment per Send

An Instance needs its Store to outlive a restart without another service to run, and the Instructor wants to read what a Student sent where they already work. **So the GitHub Store (`app.store.github.GitHubStore`) keeps each Student's record in one issue of the Instance's repository, labelled with the Store's label, and each Send as one comment on it, written by the Store App (ADR-0004).** A drawing's files go to the data branch besides (ADR-0003).

- **The issue is found by a hidden marker.** It is opened at the Student's first sign-in (`open_record`), else at their first Send. Its body is a short header (Student, Group, Evidence Project) and a hidden marker with the Student's numeric GitHub id, by which the Store finds the issue again after a restart. The body is never rewritten, and it mentions nobody with `@`, since GitHub would notify them. A closed issue still holds its record.
- **A comment is a line to read, then the Send.** The line is for a person reading the issue (`_line` in `backend/app/store/_internal/comments.py`; a question's text is quoted below it), cut at `LINE_CHARS`. A fenced block follows, info string `json practice`, holding one line of JSON: `kind`, `competency`, `step` or `drawing`, `version` and `payload`. The block is the Send, so the line may be cut: the block holds it whole. GitHub's own timestamp on the comment dates the entry.
- **Only the Store App's comments are Sends.** A comment counts only when written by the Store App's own bot login (`STORE_BOT`, or the slug the settings give), not by a person nor by any other GitHub App: the Instructor may comment on an issue, and nobody can forge a Send by pasting a block.
- **An unknown kind is skipped.** A block holding a kind this version does not know is not an error: an older Engine reads a Store a newer one wrote.
- **A second issue drops nothing.** GitHub's label search lags seconds behind a new issue, so a restart right after a first sign-in may open a second issue for the same Student. A record is therefore read from every issue carrying the Student's marker, merged by date, and its versions counted again in that order (`_renumbered`); Sends go to the Student's oldest issue.
- **A record is read once, then written through.** It is read from GitHub the first time it is asked for, then kept in memory: a Send appends to it once GitHub has stored the comment. Reading every Student's record (`records`) lists the repository's comments once, not once per Student.
- **The label is a setting** (`store_label`). Staging uses its own, so the Instructor's tests on staging never mix with the Students' issues.
- **The Instructor can read every question with `gh`.** Each question's block has `"kind": "question"`, its `competency`, its `step` and `payload.text`.
