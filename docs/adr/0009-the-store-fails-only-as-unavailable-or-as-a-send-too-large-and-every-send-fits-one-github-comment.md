# The Store fails only as unavailable or as a Send too large, and every Send fits one GitHub comment

The GitHub Store depends on GitHub, which can be down or rate-limit the Store App, and it keeps each Send as one comment, which GitHub refuses over 65,536 characters with a 422. Left to GitHub, that refusal would reach the Student as a Store failure, a 503 that says "try again" forever, which no retry can fix. A Student must know whether to wait and send again, or to change what they send, and must read why in plain words before anything is written. **So the Store fails in exactly two ways, both recording no entry: `StoreUnavailable` when it could not read or write, which the API answers with 503 and `Retry-After`, and `SendTooLarge` when a Send cannot fit one comment, which the API answers with 422 because retrying would not help. Each text a Student sends has its own limit, set so that the largest Send still fits one comment, and a text over it is refused with a 422 naming the field.**

- **Every Store measures a Send as it writes it.** Every Store, the in-memory one included, refuses a payload whose JSON, as the Store writes it (`payload_json`: one line, UTF-8 kept, escapes counted, so a newline counts two characters), is over `MAX_SEND_CHARS`, before anything is written (`check_size`).
- **`MAX_SEND_CHARS` leaves room around the payload.** It stays under GitHub's limit (`GITHUB_COMMENT_LIMIT`) with room for the comment's line to read, at most `LINE_CHARS`, and the block around the payload. The GitHub Store also checks the whole comment against the limit before posting it.
- **Each field has its limit.** `app.practice._internal.models` sets the longest text each field takes: `MAX_FIELD_CHARS` (one field of an answer), `MAX_PLAN_CHARS` (the Evidence Plan, with room above a full draft), `MAX_EXAMPLE_CHARS` (the example for the Eval), `MAX_NOTE_CHARS` (what to read in an Evidence Project) and `MAX_URL_CHARS` (an Evidence Project's URL, a "done" link). With them, the largest Send, the closing step's Evidence Plan, example, declaration and Evidence panel snapshot, fits one comment.
- **The Evidence panel's snapshot is capped.** `snapshot` in `backend/app/evidence_panel/panel.py` keeps it under `SNAPSHOT_MAX_CHARS` (40,000) characters of JSON: above it, each fact keeps its sentence and drops its file list, and the snapshot is marked `files_dropped`. A repository with very many changed files therefore keeps what each fact says, not which files it lists.
- **A refusal is one sentence the page shows as it is.** `_at_most` refuses a text over its limit with a 422 whose `detail` names the field and says it is too long, rather than pydantic's validation error.
- **The size that counts is the size once stored.** A control character takes six characters once stored (`\u0001`), so a Send within every field's limit may still be over one comment: that is the 422 "too long to store", without `Retry-After`, from `app.main`'s handler for `SendTooLarge`.
- **The Student keeps what they typed.** The screen says what was not stored, in `STORE_UNAVAILABLE` and `SEND_TOO_LARGE` in `backend/app/main.py`, and what they typed stays in the browser.
- **`backend/tests/test_send_size.py` guards it** on the GitHub Store, against `FakeGitHub`, which refuses a comment over 65,536 characters as GitHub does; `backend/tests/store_contract/test_sends.py` checks both Stores refuse a Send too large and store nothing.
