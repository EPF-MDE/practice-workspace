# The GitHub Store is tested against a fake of GitHub's HTTP API that answers as GitHub does

The GitHub Store is the Store an Instance runs on, and its failures are GitHub's: limits, refusals, lag and concurrent writers. A test double that only records calls would let the Store pass tests that GitHub would fail. **So the GitHub Store's tests run it against `FakeGitHub` in `backend/tests/fake_github.py`: an `httpx.MockTransport` that fakes only the Issues and Contents endpoints the Store calls, and answers each one with GitHub's own status codes, JSON shapes, `Link` pagination and server timestamps.**

- **Only what the Store calls.** List a repository's issues by label, open an issue, list and add an issue's comments, list every issue's comments at once; on a branch, list a folder, read a file at the branch or at a commit, and create or update a file, one commit each, refused with 409 when the file's `sha` is stale. Anything else answers 404, so a new call the Store makes shows up as a failing test rather than a silent pass.
- **It refuses what GitHub refuses.** A comment body longer than `COMMENT_LIMIT` (65,536 characters) is refused with 422, as GitHub does; the Store's size check (ADR-0009) is tested against that refusal.
- **It lags as GitHub's search lags.** `FakeGitHub.unlisted` holds issues the label search does not list yet, because GitHub's issue search lags seconds behind a new issue; the Store's handling of a second issue for the same Student is tested through it.
- **It counts what GitHub's secondary limit counts.** `FakeGitHub.writes` counts every content-generating request (every method but GET), so the write budget (ADR-0025) is measured as GitHub would count it.
- **It is thread-safe.** Every request is answered under one lock, `FakeGitHub._lock`, because the Store sends from several threads; without it, the fake, not the Store, would be the source of races.
- **It fails on demand.** `down` makes every request answer one status (such as 503 or 403), and `conflicts` makes the next file writes answer 409, as when another writer moved the branch.
- **A person can act beside the Store.** `comment_by_hand` adds a comment by a person or by another GitHub App, and `commit_by_hand` commits on a branch as another writer would, so the tests show what the Store makes of a comment it did not write and of a branch another writer moved.
