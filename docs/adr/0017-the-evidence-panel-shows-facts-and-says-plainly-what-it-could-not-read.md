# The Evidence panel shows facts, and says plainly what it could not read

A Student reads the Evidence panel to know what the Reading Day would find on their Evidence Project today. It is not graded, and must not read as a grade. An empty panel read as "you produced nothing" would mislead them when the truth is that the Practice workspace could not read the Evidence Project: GitHub failed, the Student Connector (ADR-0004) cannot read a declared repository yet, or the Evidence Project is on GitLab, which the Repository reading does not read. **So the Evidence panel shows facts, each naming the point it supports, never a grade; and every case where nothing is read says why, and says it is not a zero.**

- The fixed sentences live in `backend/app/evidence_panel/panel.py`: `empty_text`, `not_read_text` and `UNAVAILABLE`, used by `unavailable_panel`; the GitLab sentence is `not_read_on_gitlab` in `backend/app/repository_reading/reading.py`. The panel and its snapshot at the closing step (`snapshot`) share one wording.
- An empty reading (`RepositoryReading.empty`: no branch and no pull request changes a file beyond the course's code) says where it looked, with the counts of branches and pull requests read, and that it is a provisional reading, not a zero.
- `read_panel` in `backend/app/evidence_panel/source.py` reads the Evidence Project the Reading Day reads: the one declared if the Student Connector can read it, else the Roster's. A declared repository it cannot read, or a GitLab project, is said as such, and nothing else is read in its place. How a declaration's access is checked is ADR-0018.
- `read_panel` catches every exception from the reading on purpose, logs it, and returns the unavailable panel, so that the Student's Path and the closing step go on. This covers an Instance whose Student Connector has no installation yet: the panel says the repository could not be read now, and the next view tries again.
- `read_all` in `backend/app/repository_reading/batch.py` catches every exception per repository on purpose: one repository failing is named in `BatchResult.failures` and must not lose the others' readings.
- A Student has one Evidence Project for every Competency, so in the front end every panel query sits under `evidencePanelsKey` in `frontend/src/practice/evidence/EvidencePanel.tsx`. Declaring, changing or withdrawing the Evidence Project (`useEvidenceRequests` in `EvidenceProject.tsx`), or a declaration riding with the closing step's Send (`useSendPlan` in `frontend/src/practice/closing/useEvidencePlan.ts`), invalidates `evidencePanelsKey` and every Competency's query, not only the current one.
