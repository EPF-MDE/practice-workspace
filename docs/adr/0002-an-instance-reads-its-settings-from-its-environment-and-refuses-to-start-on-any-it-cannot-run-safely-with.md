# An Instance reads its settings from its environment, and refuses to start on any it cannot run safely with

An Instance's secrets and dates differ between local runs, staging and production, and none may be committed. A wrong setting found by a Student mid-Practice costs more than an Instance that does not start. **So `app.settings.Settings` reads every setting from the environment, each named `WORKSPACE_…`, the Close and the Reading Day included, and `app.main.create_app` checks those settings and the Course folder once, at start, and refuses to start on any it cannot run safely with.** The one part built later is the Repository reading, which needs GitHub and is not needed for the rest of the Practice workspace to run.

- **Settings come from the environment only.** Locally they come from the gitignored `.env` at the repository's root, and a variable already set wins over it; a deployed Instance takes them from each of its apps' settings.
- **The Close and the Reading Day are settings, not constants** (`closes_at`, `reading_day_at`). Tests move them into the past or the future, and the Instructor moves them without a deploy. A date set without an offset is read as Paris time, as the Course states its dates (`_in_paris_unless_told`).
- **The fake sign-in never runs deployed.** `WORKSPACE_SIGN_IN=fake` serves the tests and the local Playwright run only: `create_app` refuses it on Azure, and requires `WORKSPACE_SESSION_SECRET` there, which signs the session cookie.
- **The Course folder has no default.** It comes only from `WORKSPACE_CONTENT_DIR` (`default_content_dir` raises `ConfigurationError` without it), since the Engine holds no Course (ADR-0001). It is read and checked once (`load_content`): a content file the Engine refuses stops the Instance at start.
- **The Repository reading is built on first use.** Building it asks GitHub for the Student Connector's installation, and fails while that GitHub App has no installation or GitHub cannot be reached. So the Evidence panel reads through `LazyRepositoryReadingSource` in `backend/app/evidence_panel/source.py`, which builds the real `RepositoryReader` on its first read, under a lock, and keeps it once built. A failure to build it surfaces on that read, where `read_panel` turns it into the unavailable panel: the Evidence panel says the repository could not be read now, and the next view tries to build it again.
- **Locally and in tests, no GitHub is read for the Evidence panel.** `OfflineRepositoryReading` stands in, with readings set by hand or read from a folder (`repository_reading`, `repository_readings_dir`).
- **Importing the app reads nothing.** `app.main.app` is built on first access, through the module's `__getattr__`, so a test importing `create_app` never reads the real settings or reaches GitHub.
- **A deploy waits for the new revision.** `GET /api/health` answers once the Instance runs, with the revision it was built from.
