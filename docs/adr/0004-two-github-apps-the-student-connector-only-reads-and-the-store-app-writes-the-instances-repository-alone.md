# Two GitHub Apps: the Student Connector only reads, and the Store App writes the Instance's repository alone

An Instance signs Students in with GitHub, reads their Evidence Projects, some of them private, and writes its Store to the Course's repository. One GitHub App doing all three would hold write access to the Course's repository on behalf of every sign-in, and the Repository reading must never change a Student's repository. **So each Instance uses two GitHub Apps: the Student Connector (the `github_app_*` settings), for "Sign in with GitHub" and read-only access to Students' repositories, and the Store App (the `store_app_*` settings), with Issues and Contents write on the Instance's repository alone.** The Store, the Roster and the data branch are reached only with the Store App's installation, the Repository reading's saves included.

- **The Repository reading's GitHub seam only reads.** `GitHub` in `backend/app/repository_reading/github.py` has one method, `get`. A Student makes a private repository readable by installing the Student Connector on it; a public repository is readable by any installation.
- **Each request reads with the installation on its repository.** `repository_tokens` asks GitHub for the Student Connector's installation on each repository, and falls back to `installation_token`: the installation `github_app_installation_id` names, else the GitHub App's first, which reads any public repository.
- **A request's repository comes from its path.** `HttpGitHub` finds it with `repository_of`, which relies on every path being `repos/{owner}/{name}/...`: a request outside `repos/` would get a wrong token.
- **An installation is asked for once per repository.** `tokens_per_repository` caches the answer per repository, without case. A repository the GitHub App is not installed on is read with the default token and asked again only after `INSTALLED_TTL`, so a Student who installs it later is read with it without a question per request.
- **Both GitHub Apps act through `app.github_app`.** An installation token lasts an hour; `InstallationAuth.token` renews it five minutes before it expires, so a request never starts with a token about to lapse.
- **The reading relies on GitHub listing deployments newest first.** `_C2Facts._deployments` in `backend/app/repository_reading/_internal/c2.py` keeps the first production and the first staging deployment it lists as the latest of each.
